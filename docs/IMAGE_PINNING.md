# Пиннинг образов: что защищено и что нет

## Зачем

Плавающий тег уже однажды сменил libc под живой базой: timescale/timescaledb:latest-pg16
переехал с glibc на Alpine, и записанная версия коллации перестала совпадать с той,
что сообщает рантайм. Пересборка контейнера не должна менять движок под данными.

## Запинено по digest

| Сервис | Образ | Причина |
|---|---|---|
| postgres | timescale/timescaledb:2.30.1-pg16@sha256:f495f2bc… | смена libc под данными, уже случалась |
| redis | redis:7-alpine@sha256:ff02b58f… | AOF на диске, appendonly yes |
| glitchtip | glitchtip/glitchtip:latest@sha256:c245745b… | миграции схемы БД при старте необратимы |
| db-backup | postgres:16-alpine@sha256:cf78e766… | pg_dump старше сервера откажется работать |
| nginx | nginx:1.27-alpine@sha256:65645c7b… | дешёвая фиксация, дрейф патчей исключаем |

Каждая ссылка проверена через docker pull — все резолвятся.

## Не запинено: MinIO (осознанное исключение)

image: minio/minio — без тега. Запинить по проверенному дайджесту не удалось:

- Реестр отказывает анонимно: denied: requested access to the resource is denied.
- quay.io/minio/minio:latest — no such manifest.
- Локальный RepoDigests совпадает с Id образа. У pulled-образа это разные
  значения; совпадение означает, что образ загружен или собран локально, и
  Docker синтезировал «реестровый» дайджест. Реестрового манифеста за ним нет.

Попытка запинить его была откачена: ссылка, которая не резолвится, хуже
плавающего тега — на чистой машине pull упадёт.

Вместо пиннинга — архив точных байтов:

    C:\Users\osavi\backups\minio-image-20261116.tar   (59.4 MB)
    Id: sha256:14cea493d9a34af32f524e538b8346cf79f3321eff8e708c1e2960462bd8936e

Восстановление:

    docker load -i C:\Users\osavi\backups\minio-image-20261116.tar

Проверено: архив загружается, Id не меняется. В бакетах spectech-docs и
spectech-files лежит 12 МБ реальных данных, поэтому образ важен.

ВНИМАНИЕ: docker compose pull без указания сервиса попытается тянуть и MinIO, и
упадёт на нём. Тянуть адресно: docker compose pull redis nginx db-backup.

## Базовые образы в Dockerfile

| Было | Стало | Почему |
|---|---|---|
| FROM nginx:alpine (frontend runtime) | FROM nginx:1.27-alpine | версии не было вообще, дрейф через мажоры |
| FROM python:3.12-slim | без изменений | мажор зафиксирован, дрейф патчевый |
| FROM node:20-alpine | без изменений | то же |

Пиннинг сборочных слоёв по digest лишил бы автоматических патчей безопасности.
Это решение о процессе обновлений, а не устранение риска дрейфа движка под
данными — поэтому оставлены версионные теги.

## Процедура пересборки

Не делать docker compose pull вслепую и не пересоздавать stateful-сервисы без
необходимости. Обновление движка под данными — отдельная операция в окно
обслуживания, с бэкапом и проверкой коллации после.
